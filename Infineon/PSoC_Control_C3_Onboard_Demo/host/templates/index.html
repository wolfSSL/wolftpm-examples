Sealed secret — released only in the right state

A TPM can lock a secret to a measurement of the system it is in, and hand it back only while that measurement still matches. Below, the secret is sealed to one state, released in that state, and then the state is deliberately changed — whereupon the same chip refuses the same blob. The refusal at the end is the demo working, not failing.

  1. 1PCR 16 reset to a known measurement
  2. 2Secret sealed to that measurement
  3. 3TPM releases the secret
  4. !Measurement changes — PCR extended
  5. 4TPM refuses the same sealed blob

Endorsement certificates — issued at manufacture

Every TPM leaves the factory with certificates written into its own storage, signed by the manufacturer, stating what it is. The chip does not merely claim its identity — the vendor attests to it.

Measured boot — what the TPM has been told

A platform configuration register cannot be written, only extended: the new value is the hash of the old value concatenated with the new measurement. That is what makes a PCR a record of everything measured, in order, and why a changed measurement can never be quietly walked back. This is the state the sealed secret is bound to.

SPDM — an encrypted channel to the TPM

The bus between a host and a TPM is plaintext, whether it is SPI or, as on this board, I2C: a cheap logic analyser clipped to it reads every command and every response. SPDM negotiates a session key so the bus carries ciphertext instead. wolfTPM implements the responder as well as the client, so the whole thing can be demonstrated end to end.

Takes about 40 seconds.

    Post-quantum TLS 1.3 — identity key inside the TPM

    A TLS server proves who it is by signing the handshake with its private key. Here that key is generated inside a TPM and never leaves it, the signature is post-quantum ML-DSA, and the key exchange is ML-KEM — so both halves of the handshake are quantum-resistant and the identity is anchored in hardware rather than a file on disk.

    Why not the fitted part
    TLS CertificateVerify needs pure ML-DSA. This silicon implements only the pre-hash form, so creating the key returns TPM_RC_TYPE — the same limit that rules out ML-DSA attestation. The handshake below therefore runs against wolfTPM's firmware TPM, which is a socket TPM and never touches the SPI bus.
