Sealed secret — released only in the right state

A TPM seals a secret to a system state, releasing it only when the current measurement matches. Choose the matching PCR to see the plaintext returned, or change PCR before unsealing to see the TPM reject the same blob. That refusal is the security feature working, not a failure.

Endorsement certificates — issued at manufacture

Every TPM leaves the factory with certificates written into its own storage, signed by the manufacturer, stating what it is. The chip does not merely claim its identity — the vendor attests to it.

Measured boot — what the TPM has been told

A platform configuration register cannot be written, only extended: the new value is the hash of the old value concatenated with the new measurement. That is what makes a PCR a record of everything measured, in order, and why a changed measurement can never be quietly walked back. This is the state the sealed secret is bound to.

SPDM — an encrypted channel to the TPM

The bus between a host and a TPM is plaintext, whether it is SPI or, as on this board, I2C: a cheap logic analyser clipped to it reads every command and every response. SPDM negotiates a session key so the bus carries ciphertext instead. wolfTPM implements the responder as well as the client, so the whole thing can be demonstrated end to end.

    Post-quantum TLS 1.3 — identity key inside the TPM

    A TLS server proves its identity by signing the handshake with a private key. Here that key is generated and secured inside a TPM, so it never leaves hardware. With ML-DSA for the signature and ML-KEM for the key exchange, the whole handshake is quantum-resistant and hardware-anchored rather than reliant on a file on disk.

    How the board integrates into the handshake
    The TLS stack runs on the host PC but holds no private key. When the server needs to sign its CertificateVerify, it passes the handshake digest to the board, which signs it inside its socketed TPM and returns an ML-DSA signature. Current firmware signs the pre-hashed variant of ML-DSA, which has no official TLS 1.3 code point, so this demo uses a temporary value from the private-use range. Production firmware will support the standard form and remove the need for it. The TLS stack patch is included in patches/.
